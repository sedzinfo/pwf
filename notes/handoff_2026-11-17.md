## Done (commits c88898a "port" and cdcad2d "tests", pushed)
CI (ubuntu Python 3.11/3.12/3.13, windows 3.13) was red on bae0f57 and 7ea9cca. Causes and fixes:
1. src/pwf/_sem.py: test_glm_validity's CFA of dimension E was reported "did not converge" on some
   runners although its gradient was 6e-8. BFGS stops with "precision loss" and L-BFGS-B with
   "ABNORMAL" at the optimum. A fit now also counts as converged when every gradient element is
   <= 1e-3 (lavaan's check.gradient, optim.dx.tol).
2. tests/conftest.py: a Git checkout on Windows turns LF into CRLF, and read_csv(path) kept the "\r"
   inside multi-line cells (11 Windows-only failures). References are now read as text.
3. src/pwf/explore_assumptions.py: `_shapiro_wilk` is a line-by-line port of R's swilk.c (R 4.6.2),
   replacing scipy.stats.shapiro, whose p differs from R's by 2e-7 (relative) on scipy < 1.18, which
   is what Python 3.11 gets. W equals R's to 15 digits; p agrees to within 3e-13.
4. tests/test_glm_logistic_regression.py, case "case ~ education": the 0-5yrs and 6-11yrs groups both
   have fitted p = 1/3 exactly, and which one sits at the cut is decided by last-bit rounding. rwf
   itself gives 80/40/120 on Windows (the reference) and 8/4/12 on Linux (R 4.6.2 here, with any BLAS
   and any row order); pwf gives 8/4/12 here. The test now feeds rwf's fitted values into report_logistic.
Verified locally: 351/351 tests pass with the newest libraries (Python 3.12, scipy 1.18.1), with
scipy 1.17.1 + numpy 2.4.6, and on a copy with CRLF line endings (simulated Windows checkout).
