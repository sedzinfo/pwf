```r
args <- commandArgs(trailingOnly = TRUE)
lines <- readLines(file.path(args[1], "tests", "reference", "make_reference.R"))
suppressPackageStartupMessages(library(rwf))
grDevices::pdf(NULL)
out_dir <- normalizePath(file.path(args[1], "tests", "reference"))
data_dir <- normalizePath(file.path(out_dir, "..", "..", "src", "pwf", "data"))
ref <- function(name, x) {
  con <- file(file.path(out_dir, paste0(name, ".csv")), open = "wb")
  on.exit(close(con))
  utils::write.csv(x, con, row.names = FALSE)
  cat("wrote", name, "\n")
}
rule <- grep("^#{20,}$", lines)
start <- grep(paste0("^# ", args[2]), lines)
stopifnot(length(start) == 1)
following <- rule[rule > start + 1]
end <- if (length(following)) following[1] - 1 else length(lines)
eval(parse(text = lines[start:end]), envir = globalenv())
```

## Done today: the four plots, side by side with rwf
Method: rwf's ggplot_build() layer data, labels and axis ranges dumped to JSON from R, compared with plotnine's
layer data after draw(); then the same as references + tests. Every number below was checked against R here.

### plot_cfa_gg / plot_cfa (glm_sem.py)
- Tree layout: pwf used graphviz "dot" (or a 2-row fallback without graphviz, so CI and laptops differed).
  Now `_rcompat.r_layout_as_tree`, a port of igraph's Reingold-Tilford (cigraph layout/reingold_tilford.c:
  virtual root over several roots, edges to unreachable vertices, mean-centred parents). Identical to igraph on
  400 random graphs (atol 1e-12).
- Circle layout: `_rcompat.r_layout_in_circle` (igraph's cos/sin of 2*pi/n*i), equal to igraph to 1e-15.
- Spring layout: rwf's igraph layout_with_fr starts from random positions (no seed), so rwf itself differs on
  every call; pwf keeps networkx spring_layout(seed=1). Accepted, documented in the module docstring.
- Covariance arcs: grid's curveGrob (geom_curve, curvature 0.35, angle 90, ncp 5, shape 0.5) ported as
  `_rcompat.r_curve` (calcControlPoints + calcOrigin + R's xspline.c open X-spline, including its 1200 ppi step
  rule). Point for point equal to grid's xsplinePoints() on 200 random curves (1.5e-14). pwf's old quadratic
  Bezier bent the other way. Arcs now have rwf's open arrows at both ends.
- Row order of edges: rwf merges twice (by lhs, then rhs). `_rcompat.r_merge_rows` ports R's merge order:
  match codes, R's do_merge pairing after its *unstable* Shell sort (isort_with_index, src/main/util.c), then a
  stable collation sort. Equal to R on 400 random merges; matters for cross-loadings (tied rhs).
- Sizes: ggplot2 text sizes are mm, plotnine's are points. pwf drew 3.2 pt node labels (rwf 9.1 pt; unreadable),
  arrows 0.02 in (rwf 6 pt). Helpers `_rcompat.gg_text_size` (x .pt), `gg_linewidth` (ggplot2 linewidth ->
  plotnine size: x .pt x 72/96 / sqrt(pi)) and `gg_unit_pt`. Label padding and title margin as rwf.
- RWF BUG copied for parity: `plot_cfa_gg(what = "eq")` fails when the model has no labels (lavaan's
  parameterEstimates() then has no label column), so rwf's plot_cfa returns 6 diagrams, not 9. pwf's SEM engine
  cannot fit labelled models at all (labels/equality constraints raise NotImplementedError in _sem._parse), so
  pwf now always raises on "eq" and plot_cfa returns rwf's 6 keys. The old test asserted 9 keys (pwf's own
  behaviour); it now uses the reference `plot_cfa_keys`.
- Not set: ggplot2's plot.margin of 20 pt (plotnine's plot_margin is a fraction of the figure).

### plot_irt_onefactor (glm_irt.py, needs R + mirt + rpy2)

### plot_oneway_diagnostics, and the diagnostics of report_regression and report_logistic
- rwf draws ggfortify::autoplot(model, which = 1:6, ncol = 2, label.size = 3). pwf had a matplotlib sketch
  (no smoothers, no labels, a least-squares Q-Q line, 0-based Cook's distance index, suptitle caption).
- Now `glm_anova_plot._autoplot_lm`: a port of ggfortify 0.4.25's autoplot.lm (printed from R with
  getS3method("autoplot", "lm", envir = asNamespace("ggfortify"))): six plotnine panels composed with | and /
  (ggmultiplot), R's lowess smoothers, qqnorm and its quartile line, the 3 most extreme row names, Cook's
  contours from pretty(), the "Constant Leverage: Residuals vs Factor Levels" panel for equal group sizes (with
  expand_limits(x = 0)), the caption on every panel, titles left-aligned as ggplot2.
- `_rcompat.r_lowess`: port of R's clowess (stats/src/lowess.c); bit-identical to R on 300 random cases.
  statsmodels' lowess differs from R's on 88 of those 300 (see "what is left": ts_smoothing).
- `_rcompat.r_qqnorm`, `_rcompat.r_quantile7` (R's type 7 formula), `glm_anova_plot.lm_diagnostics`,
  `glm_anova_plot.model_factors`, `glm_anova_plot.r_row_names` (labels: integer index + 1, as R's row names).
- report_regression uses the same port (which = 1:6, angle 20). RWF QUIRK copied: rwf adds
  `labs(title = title)` with default title "", which blanks all six panel titles.
- report_logistic uses it too: ggfortify draws 4 panels for a glm (pwf drew 6 with Pearson residuals). The
  values come from pwf's R-style glm refit (hat values of R's last IRLS iteration). R 4.6's rstandard.glm
  default is now "pearson" (divided by sigma(model) = sqrt(dispersion)), which is what panel 5 shows.
- Checked: 60/60 + 28/28 panels equal to rwf except one family of cases below.
- ACCEPTED, not reproducible: when leverages are tied (one-way ANOVA groups), R's leverages carry last-bit noise
  in the first k rows (LINPACK QR through OpenBLAS here), which reorders ties and changes lowess's window.
  Affects the lowess line over leverage (panels 5/6) in e.g. blood_pressure agegrp with NAs (0.09 off) and
  panel 6 of balanced designs. The Q-Q panel's points are the same set (tied residuals swap quantiles). I could
  not test Windows R (reference BLAS) here. The tests use cases that agree (insurance smoker/charges).
- plotnine bug found: `composition & theme(...)` after the composition was drawn deep-copies the drawn
  figure and runs away (10 GB, minutes). pwf's report_pdf draws once and resizes, so it is not affected; don't
  use `&` on a drawn composition.
